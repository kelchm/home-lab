# Vonk model cache on Athena

Dedicated share `vonk-forge-models-pve-sbx` follows `<workload-purpose>-<consumer-cluster>`. Its root is the managed model cache, without another nested directory. Controller API and worker mount it at `/state/model-cache`. PostgreSQL, secrets, other Controller state, image archives and build caches stay local. Sparks continue to serve from local storage, including PLE/runtime caches.

`create-share.py` previews by default and applies only with `--apply`, as root on Athena. It refuses an existing path/share/export, records the previous exports, creates an unbrowsable share, and restricts NFSv4.1 access to Controller VM `10.32.21.101`. The share uses DSM’s native `admin` owner and `administrators` group, resolved by name rather than hardcoded IDs. NFS maps all requests from the allowed Controller IP to `admin`; directories are setgid mode02750 and files mode0640. Vonk retains its internal UID/GID10001. This deliberately trusts the allowed Controller host, including its root and other container identities; it does not provide per-container UID isolation. No DSM account is created or enabled. Reserved client ports are required and server writes are synchronous. No unrelated share, ACL or global NFS setting is changed. A partial failure is left for inspection rather than deleting potentially useful data. DSM creates its own `@eaDir` metadata directory; preserve it. `--resume-created --apply` can finish a newly created, unpopulated share only when this script’s creation checkpoint exists and exports are unchanged. It refuses a populated cache.

Use `compose.nas-model-cache.yaml` as a fourth overlay alongside the deployed `docker-compose.yaml`, `compose.local.yaml`, and `compose.evaluation.yaml`. After `check-volume.py` verifies the named volume options, Docker's local NFS volume driver must mount the exact export before a container can start; it cannot fall back to an unmounted host directory. `nocopy` prevents Docker from populating the share from container contents. Hard mounts prioritize data integrity: a NAS outage can block cache I/O and Controller operations. Do not force-unmount an active cache. The original local cache remains mounted underneath `/state` and must be preserved until acceptance and rollback review complete.

Run `check-volume.py` before every cutover and after volume qualification. It rejects an existing same-named plain local volume or any changed driver options. Never allow Compose to reuse an unverified volume. Before cutover, test this exact volume with disposable containers using the deployed Controller image and UID10001: file creation, fsync, atomic replacement, cross-process locks, hash verification, native owner/group and nested setgid inheritance. Run `qualify-filesystem.py --expected-owner 1024 --expected-group 101 --require-setgid` after verifying those native IDs on this NAS. Verify denial from an unauthorized client host separately; different UIDs on the authorized Controller intentionally share the mapped identity. Test an unavailable export separately and confirm no local fallback. Verify the resolved Compose changes only the two model-cache mounts and adds the NFS volume.

Check the named volume before any copy container starts. A preliminary read-only copy of immutable objects can run while services remain available, using `copy-objects.py` with a reviewed SHA256/size plan; it rejects source changes, verifies source and copied bytes, and publishes without overwriting an existing object. Before cutover, quiesce Controller API/worker cache writers, back up the local database, compare the complete source inventory with the verified destination, and copy any remaining objects and partial checkpoints while preserving the five child directories. Never copy live lock ownership; services reacquire locks on startup. All copy/import/hash processes using NFS must run as UID/GID10001 (for example, a disposable container mounting the old cache read-only and the NAS volume read-write). The NAS maps these requests to its native owner. Create directories0750 and regular files0640 as the container user; parent setgid directories preserve the native administrators group for new descendants; do not preserve foreign ownership or copy HF symlinks as symlinks. Verify every expected object hash and size. Keep the existing database and identity/trust history. Copy retained Spark/HF files only through an exact canonical-hash import plan, as regular files staged and atomically published; no fabricated database receipts or legacy runtime compatibility. Normal cache preview/download must recognize those bytes and fetch only missing approved files.

Rollback: quiesce API/worker, preserve any new NAS objects/partial checkpoints, and restore the previous three-file Compose configuration with the exact prior images and original local state volume. Restart through Compose. Do not restore an old database or rewind trust; do not assume a DB receipt proves bytes exist on the old local cache. Verify the required objects against the local cache before making a model available; either copy NAS-only objects and partial checkpoints back with hash verification or reapply the NAS mount. Missing objects require normal cache reconciliation/download, not fabricated receipts. Never use `docker compose down -v`, prune retained volumes, or delete the NAS share as part of routine rollback.

Physical acceptance and exact receipts must be recorded before marking the migration complete. NAS snapshots/backup policy are separate from the retained original cache and are not implicitly configured by this overlay.

## Native DSM identity migration

`migrate-dsm-identity.py` previews by default. Stop every NAS copier, verifier and cache consumer first; it is a metadata operation on a quiesced share. Run as Athena root with `--apply` only after reviewing the exact preview. It requires the original Controller-only, synchronous, root-to-guest NFS rule; known10001 ownership; regular files/directories; and the known initial DSM ACL, its verified one-level directory/two-level file inheritance, or plain Linux permissions. Unknown ownership, ACLs, symlinks or unexpected root contents stop the migration. DSM `@eaDir` metadata is preserved.

The migration records original ownership, modes, exact known ACL entries and export policy in a private `/var/tmp/vonk-cache-identity-*` checkpoint. It changes only cache metadata to native `admin:administrators` and the owned export’s mapping to `all_admin`. Nested setgid directories ensure new NFS files remain accessible to human DSM administrators. No model contents are rewritten. Do not run the historical `repair-dsm-visibility.py` against this native identity policy.

After applying, run the exact mapped-NFS filesystem probe, verify human administrator access to newly created nested files and unauthorized-host denial, and confirm unrelated exports are unchanged. Acceptance must precede production cutover. Isolated tests on Athena exercise apply/explicit rollback, injected NFS API failure/automatic rollback, and unrelated-export drift without rewinding that other share; these tests mock the export API and do not substitute for live NFS qualification.

For identity rollback, stop writers and run `migrate-dsm-identity.py --rollback /var/tmp/vonk-cache-identity-EXACT_CHECKPOINT`. It requires the same tree: if new objects appeared, inspect and preserve them before proceeding. The script restores saved ownership, modes, ACL entries and this share’s old NFS rule. It records unrelated export drift while preserving it. Retest the original UID10001 filesystem behavior and root/unrelated-UID denial after rollback. The independent three-file Compose rollback restores local cache use without requiring a NAS metadata rewind.
