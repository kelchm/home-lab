# Vonk model cache on Athena

Dedicated share `vonk-forge-models-pve-sbx` follows `<workload-purpose>-<consumer-cluster>`. Its root is the managed model cache, without another nested directory. Controller API and worker mount it at `/state/model-cache`. PostgreSQL, secrets, other Controller state, image archives and build caches stay local. Sparks continue to serve from local storage, including PLE/runtime caches.

`create-share.py` previews by default and applies only with `--apply`, as root on Athena. It refuses an existing path/share/export, records the previous exports, creates an unbrowsable share, and restricts NFSv4.1 access to Controller VM `10.32.21.101`. The new share uses numeric UID/GID `10001:10001` and POSIX0750 to match Vonk's fixed runtime identity; no DSM login account is created. Root is squashed to guest, reserved client ports are required, and server writes are synchronous. No existing share, ACL or global NFS setting is changed. A partial failure is left for inspection rather than deleting potentially useful data. DSM creates its own `@eaDir` metadata directory; preserve it. `--resume-created --apply` can finish a newly created, unpopulated share only when this script’s creation checkpoint exists and exports are unchanged. It refuses a populated cache.

Use `compose.nas-model-cache.yaml` as a fourth overlay alongside the deployed `docker-compose.yaml`, `compose.local.yaml`, and `compose.evaluation.yaml`. After `check-volume.py` verifies the named volume options, Docker's local NFS volume driver must mount the exact export before a container can start; it cannot fall back to an unmounted host directory. `nocopy` prevents Docker from populating the share from container contents. Hard mounts prioritize data integrity: a NAS outage can block cache I/O and Controller operations. Do not force-unmount an active cache. The original local cache remains mounted underneath `/state` and must be preserved until acceptance and rollback review complete.

Run `check-volume.py` before every cutover and after volume qualification. It rejects an existing same-named plain local volume or any changed driver options. Never allow Compose to reuse an unverified volume. Before cutover, test this exact volume with disposable containers using the deployed Controller image and UID10001: file creation, fsync, atomic replacement, cross-process locks, hash verification and denial for a different UID. Test an unavailable export separately and confirm no local fallback. Verify the resolved Compose changes only the two model-cache mounts and adds the NFS volume.

Check the named volume before any copy container starts. A preliminary read-only copy of immutable objects can run while services remain available, using `copy-objects.py` with a reviewed SHA256/size plan; it rejects source changes, verifies source and copied bytes, and publishes without overwriting an existing object. Before cutover, quiesce Controller API/worker cache writers, back up the local database, compare the complete source inventory with the verified destination, and copy any remaining objects and partial checkpoints while preserving the five child directories. Never copy live lock ownership; services reacquire locks on startup. All copy/import/hash processes using NFS must run as UID/GID10001 (for example, a disposable container mounting the old cache read-only and the NAS volume read-write). Squashed root cannot access the share. Create directories0750 and regular files0640 as that user; do not preserve foreign ownership or copy HF symlinks as symlinks. Verify every expected object hash and size. Keep the existing database and identity/trust history. Copy retained Spark/HF files only through an exact canonical-hash import plan, as regular files staged and atomically published; no fabricated database receipts or legacy runtime compatibility. Normal cache preview/download must recognize those bytes and fetch only missing approved files.

Rollback: quiesce API/worker, preserve any new NAS objects/partial checkpoints, and restore the previous three-file Compose configuration with the exact prior images and original local state volume. Restart through Compose. Do not restore an old database or rewind trust; do not assume a DB receipt proves bytes exist on the old local cache. Verify the required objects against the local cache before making a model available; either copy NAS-only objects and partial checkpoints back with hash verification or reapply the NAS mount. Missing objects require normal cache reconciliation/download, not fabricated receipts. Never use `docker compose down -v`, prune retained volumes, or delete the NAS share as part of routine rollback.

Physical acceptance and exact receipts must be recorded before marking the migration complete. NAS snapshots/backup policy are separate from the retained original cache and are not implicitly configured by this overlay.

`copy-objects.py` handles only CAS `objects/<prefix>/<sha256>` plans containing `sha256` and `bytes`. It rejects path-based imports; retained Spark/HF imports and partial checkpoint synchronization require separate explicit tooling. This Controller cache currently has no partials or manifests; the cutover must reject any newly appearing ones until they are synchronized. `--jobs` permits 1–4 independent object copies. Startup refuses orphaned `.import-*` files: inspect them and confirm no importer is running before removing only incomplete staging files or moving them to quarantine. Canonical destination objects are never overwritten.

Client read-back can be served from the NFS client cache, even from another process. Before cutover, independently hash every completed object on Athena and compare to the approved object plan; a fresh client process alone is not evidence of server-side read-back. Server `fsync` and ordinary NFS integrity still apply, but this independent hash pass is the migration acceptance evidence.
