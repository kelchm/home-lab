# Vonk recipe-v1 evaluation candidates

These are local evaluation recipes for two DGX Sparks, prepared against Vonk Forge published source `3cacd73b7817ae884a90d1749380bb1cc246f680` and compatible recipe-library revision `5bbb0be4e604768499ccbcf82bbea181575c31d6`. They preserve immutable source, image and model identities. Structural validation is not GPU qualification; all recipes remain candidates until the actual experiments below pass. FLUX has separate public-build and offline-build variants, preserving evidence when a platform defect blocks one construction path. Shared cluster changes are serialized by the evaluation orchestrator, and the existing Qwen service plus retained model/image caches are rollback assets.

Qwen deliberately uses the September 3 NVIDIA metadata available to the September 5 reports. The September 5 23:36 revision changes only README and config.json; all 11 weight shards and the legacy quantization sidecar match byte-for-byte. It changes the MTP algorithm spelling from `FP8_BLOCK_SCALES` to `FP8_PB_WO`, which the pinned Mia helper rejects. Keeping coherent earlier metadata avoids inventing a runtime normalization change. The exact chosen configs were exercised locally: both receive absolute MTP aliases, the original files remain unchanged, and repeated launches get distinct writable views. The first profile omits the FP8 sparse-attention KV patch and reduced draft vocabulary, so its throughput must not be labeled a reproduction of the X headline profile.

The first Qwen build failed before downloading layers because its build download budget equaled the compressed-layer byte sum. The controller also uses that field as the maximum complete base OCI archive size, which includes image config, manifest, index and tar padding. The corrected envelope is 12 GB; the expected compressed layers remain exactly 9,702,868,146 bytes. The normal retry on Spark 1 succeeded, finalizing a verified 20,837,629,952-byte archive at September 6 12:03:56 UTC, within the separate 40 GB final image allowance. Base import took 112 seconds, Dockerfile construction 287 seconds and export about 45 seconds; upload is measured separately by the platform evaluation. The same inherited layer-sum budget error existed in the GLM fallback (9,788,994,117 compressed bytes), so its base archive envelope is also corrected to 12 GB. Public-build FLUX already has a 25 GB download/archive envelope for a 1,765,183,632-byte compressed CUDA base plus dependency downloads; offline FLUX uses a 12 GB envelope for its 9.58 GB compressed base. All four recipes have 40 GB final image caps; only Qwen's actual exported size is established so far.

The built Qwen image's embedded receipt pins Mia `c2325b22` and the exact NVIDIA base, and its recorded patched PLE/modelopt SHA256 values match the files in the exported archive. Actual installed metadata is torch `2.13.0+cu130` with CUDA 13.0 and vLLM `0.1.dev20073+g8e685d198`; the base image's build-commit label remains `unknown`, so the short version suffix is not presented as a separately verified full source revision. Build imports and CLI/helper checks passed; ARM64, UID 10001, the cleared entrypoint and runtime-interface label were verified from the final image configuration. This establishes image construction and source integration; normal model installation and distributed GPU qualification remain pending.

The GLM image is deliberately the compatible library pin. The September 5 Mia head `3021f24c88a0904c768c46ff22a508407e31360a` is 21 commits newer and adds E2 fat-expert prefill, workspace sizing, template/prefix-cache changes, spinwait controls and experimental TP4. We cannot attribute those newer performance claims to this older image. Larger context and concurrency are bounded opt-in experiments, not established capacity. Memory reservations are conservative estimates to test, not measured success.

Both distributed runtimes select the observed primary RoCEv2 GID3 rail: `enp1s0f0np0` / `rocep1s0f0`, addresses `198.19.240.11` and `.12`. The secondary `enP2p1s0f0np0` / `roceP2p1s0f0`, `198.19.241.11` and `.12`, is active and preserved but unused. Stock GLM f1 names refer to down ports here. These are local bindings; they are not portable discovery defaults.

## Integration findings and validation

FLUX's original script lacked a shebang, producing `Exec format error` when executed directly. Its model linker treated directory-mounted HTTP artifacts as files; the corrected workflow names each artifact's actual basename and rejects missing/nonregular files before linking. ComfyUI user/temp paths and dependency caches now stay in writable per-job temporary storage. The image records build-time imports for torch 2.13.0, torchvision 0.28.0 and torchaudio 2.11.0 plus `pip check` and supported CLI flags. The unusual torchaudio version is present on the official ARM64 CUDA13 wheel index and its metadata declares no `Requires-Dist`; real imports remain the ABI check. `download-r2.pytorch.org` is explicitly allowed because the official index directly links those wheels there; this is not a wildcard or a speculative redirect allowance.

A real build preview exposed a controller gate that demanded the observed `recipe.build.egress-proxy.v1` inventory feature in the unrelated agent claim list. The installed helper and fresh inventory were valid. The performance lane fixes that duplicate gate while retaining fresh inventory validation. No egress bypass was used. After the controller gate correction, the real FLUX build successfully imported its base image but failed while starting the native egress proxy, before executing the Dockerfile. The proxy container was created and immediately removed without a start event; the public API collapses the failure into an unsupported-network-policy message. A controlled tiny proxy reproduction confirmed that the native agent mount namespace hides `/dev/net/tun`: rootless networking fails with an explicit `slirp4netns` ENOENT. A fresh clean user-manager lifecycle sees the TUN device and gets past that failure, but encounters an additional internal-network lookup error after successful network creation. No service hardening has been changed, and a complete public-egress workaround is not yet qualified. Build output is captured into a bounded in-memory buffer and then reduced to diagnostic classes, so detailed stdout/stderr is not retained as a normal observable build log.

The separate offline FLUX variant avoids that native proxy construction path using an immutable community ARM64 image created April 30. This is a practical construction fallback, not a newly released model/runtime or a vendor-supported image. The installed ComfyUI 0.20.1 core files and GPL license byte-match their upstream revision; Kitchen's ARM64 CUDA binary matches its official 0.2.8 PyPI wheel. The publisher repository has no aggregate license or signed build attestation. Its startup updater is cleared. Our adapter uses the baked Python virtualenv, disables custom/API nodes and compile, and explicitly redirects SQLite plus inherited HF/pip/ccache paths to per-job temporary storage. Build checks require exactly torch 2.9.1+cu130 with CUDA 13.0, torchvision 0.24.1, torchaudio 2.9.1, Kitchen 0.2.8 and Triton 3.5.1 imports, `pip check`, exact core source hashes, the actual generated CLI and all 13 workflow node schemas in CPU mode. The resulting bounded receipt remains in the image; GPU NVFP4 execution and image quality still require real jobs.

Existing Hugging Face caches cannot currently be reused by Vonk's installer. The native artifact materializer reuses only its own hash-addressed cache with a validated `.vonk-manifest.json`; otherwise it stages and curls every repository file, without HF-cache lookup or interrupted-transfer resume. For GLM, retained target weights match the selected target despite README revision differences, but the retained draft weights differ. No cache manifests or installation receipts are fabricated. Normal installation can therefore incur approximately 356 GB of redundant target/draft downloads for the fallback; this is a significant operational cost worth measuring separately from raw network throughput.

Run local checks with a Python environment containing the published controller dependencies, `jsonschema` and `cryptography`:

```sh
python3 -B proxmox/guests/vonk-forge/recipes/test_adapters.py
python3 -B proxmox/guests/vonk-forge/recipes/prepare.py \
  --published-source .private/vonk-evaluation/platform-published \
  --library-source .private/vonk-evaluation/recipes-published \
  --output .private/vonk-evaluation/pass2-recipes/bundles
```

`prepare.py` validates the actual recipe-v1 schema, catalog references including nested model/group identities, artifact byte accounting, source bundle round trips and each rank's compiled command. Qwen's compiled commands are also passed through its launch validator, catching duplicate compiler-owned topology flags. Use `--refresh` only after an intentional source edit; it updates source and patch identities together. The 11 adapter regressions cover executable dispatch, actual directory mounts, writable launch state including the offline variant's SQLite/inherited caches, bounded GLM settings, Qwen rank/owned-argument checks and repeated model-view creation without artifact mutation.

## Real experiment acceptance

FLUX must pass normal catalog/source import, build, image upload/distribution and model installation, then emit a valid 1024×1024 PNG through the media job/output API. Record cold and warm wall time, phase timing, per-node memory and the image for visual review. Preserve the exact workflow/seed/prompt and logs. Check failure output and stop/cleanup behavior rather than treating a built image as working inference.

Qwen must pass image import/version/patch receipts and normal independently verified model installation on both nodes. Before launch, stop competing GPU workloads through normal lifecycle APIs. Record both rank logs continuously, NCCL world size two and IB/RoCE transport on the selected HCA, and simultaneous per-node GPU/memory measurements during the same real inference. A pair of containers is insufficient distributed evidence. Measure cold startup, a simple completion, reasoning with an explicit token budget, automatic tool calling, a deterministic needle retrieval prompt, and concurrency-one/two throughput using identical prompts. A short vision request can test the enabled image path after text acceptance. Record exact generation settings and separate prefill from decode. Larger context, FP8 KV and reduced draft vocabulary require their own measured revisions. Restore the retained single-node Qwen route after the experiment if the candidate is not accepted.

Each source folder's `UPSTREAM.md` records its precise provenance and license limits. Qwen's repository explicitly grants AGPL-3.0-or-later in its pinned README and retains full license text; vLLM is Apache-2.0 and NVIDIA model terms are separate. GLM's EXL3 checkpoint has ShapleyMCG terms and the chosen DFlash2 draft is CC-BY-NC-ND-4.0. Local evaluation does not republish model derivatives or imply a license grant beyond those upstream terms.
