# Installed cuSPARSELt metadata correction

This pinned community image's NVIDIA cuSPARSELt 0.8.0 distribution has an invalid internal `py3-none-manylinux2014_sbsa` WHEEL tag. Its official filename identifies ARM64. The unchanged Vonk build imported Torch 2.9.1+cu130, TorchVision, TorchAudio, Kitchen and Triton, then failed full `pip check` on this one unsupported-platform diagnostic. The failed revision and original source bundle remain preserved in evaluation evidence.

The [official PyPI wheel](https://pypi.org/project/nvidia-cusparselt-cu13/0.8.0/) is 220,791,277 bytes, SHA-256 `400c6ed1cf6780fc6efedd64ec9f1345871767e6a1a0a552a1ea0578117ea77c`; the [PyTorch cu130 index](https://download.pytorch.org/whl/cu130/nvidia-cusparselt-cu13/) links the same digest. Its WHEEL and METADATA byte-match the installed files. The official `libcusparseLt.so.0` is 273,881,681 bytes, SHA-256 `20de6b36cbbf5753b26826eec753a2005608e14cbc3bfdd4681138098be86941`, ELF64 little-endian AArch64 (183). Its ELF version requirements include GLIBC_2.27 from libm and GLIBC_2.18 from libc. Therefore the filename's manylinux2014 claim is also broader than this binary supports.

`repair_cusparselt_metadata.py` corrects only the installed WHEEL tag to **`py3-none-linux_aarch64`** and its hash/size row in RECORD. PyPA defines this basic platform from normalized `sysconfig.get_platform()`; manylinux2014 instead promises glibc 2.17 compatibility. The correction is scoped to this pinned container and makes no portable public-wheel claim. [Platform tag specification](https://packaging.python.org/en/latest/specifications/platform-compatibility-tags/)

Before writing either file, the script requires Linux/aarch64, matching Python platform and supported tag, glibc >= 2.27, exact Torch 2.9.1+cu130/CUDA 13.0 and dependency metadata, every original package file's hash/size, exact installed RECORD and official full-library identity. It confirms the real Torch import maps this same library and that the dynamic loader resolves it with `RTLD_NOW`. It then requires full pre-correction `pip check` to report exactly the single known tag error. Unexpected metadata, architecture, library, ABI, dependency conflict or repeated application fails before any write.

The script preserves all other WHEEL bytes, CSV row order, CRLF and RECORD's blank self-entry. It recomputes the changed WHEEL row with URL-safe SHA-256 and verifies all package files and rows afterward, following the [RECORD specification](https://packaging.python.org/en/latest/specifications/binary-distribution-format/). Full unfiltered `pip check` must then pass. The bounded `/opt/vonk/cusparselt-metadata-correction.json` records before/after hashes, official provenance, glibc, actual loader path and both dependency checks. Existing full runtime imports, Comfy core hashes, adapter CLI and CPU node-schema checks remain mandatory; real GPU generation is a separate qualification gate.

No executable bytes, dependency versions, headers, license files or model artifacts are changed or included in this source bundle. NVIDIA's original license stays intact in the parent image. The [merged verl PR 7627](https://github.com/verl-project/verl/pull/7627) corroborates the 0.8.0/0.8.1 internal-tag defect and switches its newer Torch environment to 0.9.1. That changes the library layout and does not satisfy this image's exact Torch requirement for 0.8.0. No NVIDIA acknowledgment or support for this local correction is claimed.
