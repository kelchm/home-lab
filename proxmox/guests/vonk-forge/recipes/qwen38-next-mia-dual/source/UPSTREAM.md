# Pinned source and evaluation adapter

This source bundle adapts [MiaAI-Lab/Qwen3.8-Flash-Next-Dual-DGX-Sparks at c2325b22602b51a5faf55fc2bebccc34f3f80b9f](https://github.com/MiaAI-Lab/Qwen3.8-Flash-Next-Dual-DGX-Sparks/tree/c2325b22602b51a5faf55fc2bebccc34f3f80b9f), committed September 5, 2026. The full upstream source archive SHA-256 is `fb8bbc7b241153278f68d754544e25c187fb43e7684ff9187996ca73e602e7bf`. Upstream relicensed this revision to **AGPL-3.0-or-later**, including its inherited patches; it is not MIT. The complete upstream license is retained at `upstream/LICENSE`; unchanged selected source files retain their notices and individual SHA-256 values in `upstream-sha256.json`. The new glue scripts and Dockerfile in this directory are distributed under AGPL-3.0-or-later. vLLM and its dependencies retain their separate licenses in the image. No model weights are included or republished.

The base is the official `vllm/vllm-openai:qwen38-flash-next` ARM64 manifest `sha256:3b0e188ffceb3d07e09c3cb5215433a0020eacf02d7f882ed3a8bfd15454477e`, whose config digest is `d464f3b466fa9c45ddbff8a812e80564503b6879a9fd95c1a47514f3f0df5a4a`. The config matches the image identity recorded by Mia, but labels report the vLLM commit as `unknown`. The build records import versions and actual before/after source hashes rather than inventing a Git revision.

The build applies precisely three unchanged upstream scripts. `patch_ple_layer.py` selects FP8 or packed NVFP4 PLE embedding handling from the checkpoint declaration even when the main model uses mixed precision. `patch_modelopt_mxfp8.py` routes unsupported per-partition MXFP8 matrix shapes and vision layers through the existing BF16 emulation implementation, avoiding unsupported GB10 GEMMs without dequantizing the entire model. `patch_modelopt_fp8_block_moe.py` wires MTP routed experts to vLLM's existing FP8 block-scaled MoE implementation, taking the block size from the checkpoint. These are upstream dispatch and compatibility changes; this adapter adds no new GPU kernel. Build-time checks verify input script hashes, patch anchors, Python syntax and imports, and emit a patch receipt before image export.

The model pin is [NVIDIA Qwen3.8 Flash Next NVFP4 at fab0aecb760cec45227f6656abcaafa11abca87a](https://huggingface.co/nvidia/Qwen3.8-Flash-Next-NVFP4/tree/fab0aecb760cec45227f6656abcaafa11abca87a), September 3, 2026, totaling 132,734,506,208 bytes. This is the version available to the September 5 Mia/X measurements. The later September 5 23:36 revision `fc694b54fb0174e0913e6adf86691ef85a4ead47` changes only README and config.json; its weight shards and legacy quantization sidecar are identical. Its config changes MTP `FP8_BLOCK_SCALES` to `FP8_PB_WO`, causing the pinned Mia preflight to reject it. Choosing the earlier coherent metadata avoids adding an unverified quantization normalization patch. Model license: NVIDIA Open Model License, separate from the code license.

At launch, `vllm-wrapper.py` checks the controller's exact two-rank topology, bounded profile, and rendezvous/fabric injection. It verifies original checkpoint config hashes, then calls unchanged upstream `patch_checkpoint_config.py` to add the absolute MTP layer-index aliases in both config files. Small derived files live in a fresh per-launch directory under writable outputs; every weight remains a symlink to the normal installer-verified read-only artifact. The adapter also declares the checkpoint's FP8 PLE dtype in the private config view. It does not alter model artifacts, the downloader cache, or installer receipts. Repeated launches can reuse the same output namespace safely.

The first profile uses full-vocabulary MTP3, TP2 plus expert parallelism, BF16 KV (`auto` with a BF16 checkpoint), 65,536-token context, two sequences, and 0.75 GPU memory utilization. It applies no FP8 QSA patch, reduced-draft-vocabulary patch, or YaRN extension. Mia documents a reasoning-quality regression with FP8 sparse-attention KV; that optimization needs a separately measured revision. The September X headline uses a balanced 65K draft vocabulary and a different memory/KV profile, so this is not an exact reproduction of its 53–54 tokens/s claim.

The initial per-node experimental resource contract is 110 GB startup, 102 GB steady plus 8 GB growth, and 8 GB system reserve. Upstream reports approximately 64.3 GiB resident weights with MTP. On the observed 130.66 GB host, 0.75 utilization targets about 98 GB, leaving about 12 GB within the startup envelope for other initialization overhead. Context above 65,536 or sequence count above two is an opt-in experiment, not a qualified capability. Both rank profiles select the observed primary `enp1s0f0np0` / `rocep1s0f0` RoCEv2 GID3 rail; these names are site-specific. The second physical rail remains available but unused by this profile. Real NCCL IB transport, both GPUs doing work, memory, generation quality, tools, needle retrieval and throughput must be measured before local qualification.
