## Implemented native behavior

- `cuda_images.Images.begin` validates and borrows request-owned descriptors without materializing or encoding history. `Leader.chunk` prepares only media overlapping that step. Whole-prompt serving also uses this protocol for requests containing media; text retains its original path. Cached complete media are skipped. A cached prefix cutting an image or video group only consumes its remaining rows.
- One shared feature allocation per CUDA rank replaces per-stream full-budget allocations. This source uses 4096-row chunks and permits paired steps, so the allocation holds 8192 active rows plus at most one 16384-row group: **192 MiB total per rank**, independent of history and stream count. Image-only configuration with no video budget uses 80 MiB. `streamBytes()` contributes zero additional media rows per stream. The allocation happens before memory admission measures room, so the pool cannot spend its reservation. Tower weights/workspaces, KV state, maps, and pinned staging remain separate.
- Each overlapping input passes through its original complete grid and tower. A boundary-crossing input uses the single-group scratch region, then copies only its overlapping rows into the compact active span buffer. No history, token, frame, or quality pruning is used. The unchanged defaults remain 50 images × 2048 ceiling / 102400 total, four clips × 16384 ceiling / 32768 actual total, and 128 sampled frames per clip.
- CPU materialization uses one image/group arena at a time. GLM CUDA video plans retain encoded request bytes and per-group geometry/indices, without retaining decoded frames or float patches. The native server opens/closes a decoder per requested group; each GLM decode request contains at most two sampled frames, with unchanged odd-frame duplication, resizing, normalization, and grid. Native adapter contexts are arena-owned rather than retained stack pointers. Non-GLM offers remain eager, and GLM Metal video retains its existing eager path.
- Image callbacks carry the original preparation deadline; GLM lazy videos carry the original 120-second video deadline. Cancellation/deadline checks surround image decode/resize/patchification, group decode, each returned frame's resampling, and tower completion. Cancelled lazy work still sends an empty image step and a chunk whose existing rank-wide gate handles cancellation and interrupted-prefix capture. Ordinary materialization failures send no forward header. The wire order is pending keep, image header/span words, nonempty feature-row broadcast, then chunk header/IDs and the existing forward collectives.
- Completed steps drain before invalidating their spans. Interleaving stores only request descriptor slices, never per-stream feature buffers. Reset, release, failed activation, cancelled/failed materialization, and failed release drop the appropriate spans/borrows. Failed tower operations drain before freeing tower scratch. Request arenas own encoded sources; released slots do not retain a live request borrow.
- Lazy video cache identities use a new encoded-byte/processor/normalization/geometry/sample-index namespace. They deliberately miss old eager-pixel identities. Image identities and processor quality are unchanged.

## Boundaries and remaining qualification

The mandatory CUDA feature/history ownership layer is integrated and tested on CPU. GPU numerical equivalence, actual multi-rank liveness under faults, real codec behavior, four-clip throughput, real pinned/device/host peaks, and fresh/resumed/disk-restored model output remain unqualified. This patch provides no checkpoint durability receipt. Complete 080 integration and real checkpoint/GPU acceptance are separate work.

This bounded implementation can re-decode/re-encode an image/group when it crosses another chunk or is replayed. Reopening each video group may re-scan earlier frames; decoder seek/reuse performance is not qualified. Deadlines are absolute and include queue/prefill time before lazy work. Cancellation is cooperative: a decoder/library call or queued tower operation already in progress is checked at the next callback/return, not preempted. Metal still has its existing feature-row allocation/eager prompt encoding and requires its own capacity/device qualification. The previous JPEG/WebP/EXIF/alpha/CMYK/MPO and optional PDF limits from `../media/README.md` remain.

A separate run of maintained `test-glm-prompts-host` gives six passes and the same one failure on both the untouched baseline and the patched source: `context window cut preserves sequence positions independently of tap offsets` expects `DrafterContextTooWide` at offset 2044 + 5 even though this supplied engine has 4096-row capacity. `baseline-prompt.log` records the independent baseline result; the unrelated fixture is not modified or counted in the passing focused gate. No broad-suite-green claim is made. Zig 0.17 may print `failed command` alongside successful tests that emitted stderr (`run test w`); the gate checks the actual exit code and final build summary.
