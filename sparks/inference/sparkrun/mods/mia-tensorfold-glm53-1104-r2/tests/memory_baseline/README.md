# Production Python memory baseline

The four-stream Python profile uses **one KV row pool for active histories and idle retained prefixes**. `TF_GLM_CACHE_GIB=12.5` contributes to that allocation; it is not a second 12.5 GiB row cache beside the observed 2,582,528-token pool. Earlier conversation reports describing those as two independent capacities double-counted the row memory.

In the selected kit's multi-stream constructor, the engine reserves fixed kept-state costs, adds the remaining cache allowance to the engine window's row capacity, and sets `self.cache_bytes = 0` because kept rows live in the common pool. Kept KDA/convolution/index/DFlash2 state still lives outside the row pool. The production profile requests 32 kept entries and leaves `TF_GLM_KEPT_BYTES_GIB=0`; the 12.5 GiB setting is therefore not a hard cap on all retained device state. The separate NVMe quota remains 64 GiB per rank.

This follows [multi-stream allocation in patch 0030](https://github.com/MiaAI-Lab/GLM-5.3-Flash-EXL3-2x-DGX-Sparks-TensorFold/blob/bf5f94523a8251029cedae86bf61f8ce37fac218/patches/0030-glm-multi-stream-engine.patch), with [0128's pinned read-ahead accounting](https://github.com/MiaAI-Lab/GLM-5.3-Flash-EXL3-2x-DGX-Sparks-TensorFold/blob/bf5f94523a8251029cedae86bf61f8ce37fac218/patches/0128-glm-spill-blocks.patch) and later kit changes applied. The [receipt](receipt.json) records the final source hashes and all three guarded upstream file matches against the production lock. All 123 kit patches were reconstructed off-host from the exact engine/kit archives. No Python model code, GPU or Spark operation was executed.

Qualification must compare total pool capacity, active-versus-idle sharing, kept fixed-state overhead, eviction/resume behavior and token-equivalent disk retention. Requiring an additional independent 12.5 GiB row cache would impose a capability production does not have. Native copied-snapshot storage is a different allocation design; sharing retained page ownership with the live pool is the intended direction. This correction does not establish that the proposed native allocation fits or that its reuse latency matches production.
